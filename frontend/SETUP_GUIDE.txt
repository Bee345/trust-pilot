PART 4 - TROUBLESHOOTING
================================================================================

Q: I get "Husky hook not firing on Windows"
A: Run from trust pilot/ root:
     rm -rf .husky
     npx husky init
   Then recreate the hook files (pre-commit and commit-msg).

Q: ESLint complains about my Prettier formatting
A: ESLint and Prettier are fighting. Make sure ESLint extends "prettier" LAST
   in the extends array - that turns off any rules that conflict.

Q: SonarCloud says coverage is 0%
A: The backend test workflow uploads lcov.info as an artifact. If the upload
   or download step fails, SonarCloud has no coverage file. Check the CI logs
   for the "Upload coverage to artifacts" step in GitHub Actions.

Q: Vercel deploy succeeded but the page is blank
A: Open browser DevTools -> Console tab. Most common cause: VITE_API_URL env
   var not set in Vercel, so frontend calls http://localhost:3000 which doesn't
   exist in production. Fix in Vercel project settings, redeploy.

Q: Railway deploy crashed immediately
A: railway.app -> service -> Deployments -> click latest -> View Logs.
   Most common causes:
     - Missing required env var (e.g. JWT_SECRET)
     - Supabase URL pointing at wrong project
     - Start script can't find src/server.js

Q: Paystack webhook isn't being received
A: 1. Paystack dashboard -> Settings -> Webhooks -> check delivery log
   2. Verify the URL has no typos and points at Railway (not localhost)
   3. Your webhook handler must respond with 2xx. If it 500s, Paystack retries
      3 times then gives up.
   4. Check Railway logs for the request hitting /api/verify/webhook.

Q: Sentry shows no errors but the app definitely crashes
A: DSN typo. Verify SENTRY_DSN is set on Railway and VITE_SENTRY_DSN on Vercel.
   Add a temporary /debug-sentry route to force an error and verify it lands
   in Sentry. Delete the route after testing.

Q: commitlint rejects all my messages
A: Read the rejection text carefully - it tells you exactly which rule failed.
   Most common: missing the ":", type not in the allowed list (must be one of
   feat/fix/chore/docs/test/refactor/style/ci), or description starts with
   a capital letter.

Q: "MCP server failed to start"
A: Open a terminal and run the exact command from your config:
     npx -y @postman/mcp-server
   If it errors, the package name is wrong or your network can't reach npm.

Q: I added an MCP and Claude doesn't see it
A: You edited settings.json while Claude Code was running. Servers only
   register at startup. Close all Claude Code windows, then reopen.

SECTION 0 — WHO YOU ARE IN THIS SESSION
================================================================================

Six concurrent roles. Every task falls under at least one.
State which role is acting when you flag something to the human.

ROLE 1 — ARCHITECT
  Owns: layer boundaries, naming conventions, folder structure, separation of
  concerns. Every feature must fit: routes → middlewares → controllers →
  services → models → config. No collapsing layers. No skipping layers.

ROLE 2 — SECURITY ENGINEER
  Owns: AppError usage, secrets management, input validation, rate limiting,
  RLS posture, Paystack HMAC, JWT hygiene, audit logging, error sanitisation.
  No raw error exposed to client. No stack trace in production. No hardcoded secret.

ROLE 3 — BACKEND DEVELOPER
  Owns: Node.js / Express v5 / CommonJS. Senior level: every function one job,
  max 30 lines, early returns, max 3 nesting levels, no magic numbers, no
  console.log. Dependency injection for all testable units.

ROLE 4 — FRONTEND DEVELOPER
  Owns: React 19 / Vite / React Router v7 / plain JSX. Clean Code:
  custom hooks for all data fetching, Context for global state, presentational
  components only. WCAG compliance on all interactive elements.

ROLE 5 — DEVOPS ENGINEER
  Owns: GitHub Actions CI/CD, branch protection, env var discipline,
  .gitignore, Railway and Vercel pipelines, SonarCloud, Sentry wiring.
  Tags every human action: [HUMAN — BROWSER], [HUMAN — TERMINAL], [HUMAN — DASHBOARD].

ROLE 6 — QA ENGINEER
  Owns: Jest + Supertest (backend), React Testing Library (frontend).
  Security test cases required for every sprint. Never mocks the database
  in integration tests. Coverage target: 70%+.

  feat | fix | chore | docs | test | ci | refactor | security | wip

Branch check at start of every session:
  git status && git branch && git log --oneline -5
Report what you find before proceeding.

After every PR is merged:
  git fetch origin
  git rebase origin/main
Then continue on the feature branch.

================================================================================
SECTION 4 — WHAT NEVER GOES IN THIS CODEBASE
================================================================================

No raw Error objects — AppError factories only.
No console.log — pino logger only (backend), silence (frontend).
No password_hash in any API response.
No stack traces in production responses.
No magic numbers or strings outside constants/index.js.
No import/export in backend files — CommonJS only.
No business logic in models.
No direct Supabase calls in controllers.
No direct io import in services.
No .env committed to git.
No features beyond sprint scope.
No mocking the database in integration tests.
No anon Supabase key in backend.
No service_role key in frontend.
No documentation files in .gitignore.
No sprint execution without three-list proposal reviewed in Claude.ai.
No architectural decision made autonomously.
No PR merged without CI passing.
No commit directly to main.
No WCAG violation in any frontend component shipped in a PR.
No unhandled promise rejection in backend — every async path has error handling.
No TODO comment left in committed code.

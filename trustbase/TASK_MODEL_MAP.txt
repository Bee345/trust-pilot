================================================================================
TRUSTBASE — CLAUDE MODEL TASK ALLOCATION + AGENT SWITCHING GUIDE
================================================================================
Goal: Use the cheapest model that can do the job correctly.
Do NOT waste Opus 4.7 on tasks Sonnet 4.6 or Haiku 4.5 can handle.

MODEL TIERS:
  Haiku 4.5   — Fast, cheap. Simple well-defined tasks. Low reasoning load.
  Sonnet 4.6  — Balanced. Your daily coding workhorse. Most tasks go here.
  Opus 4.7    — Deepest reasoning. Expensive. Architecture, security, ambiguity.

================================================================================
PART A — HOW TO SWITCH BETWEEN MODELS (Practical Guide)
================================================================================

Claude Code is started from your terminal. The model is set when you OPEN
a new session — you cannot change it mid-conversation.

### Method 1: Start session with specific model
Open a new terminal and type:

  For Haiku 4.5 (documentation, simple tasks):
  claude --model claude-haiku-4-5-20251001

  For Sonnet 4.6 (default, daily coding):
  claude

  For Opus 4.7 (architecture, security):
  claude --model claude-opus-4-7

### Method 2: /fast toggle (while in a session)
  Type /fast in Claude Code to switch to Opus 4.7 with faster output.
  Type /fast again to switch back to Sonnet.

### Method 3: Change your default model
  Type /config in Claude Code → change "Model" setting
  This persists across all future sessions.

### Method 4: For a SPECIFIC TASK within a session (sub-agent)
  When you ask me to do research, search code, or explore files,
  I internally spawn a specialized sub-agent. You don't need to do anything —
  just describe the task and I pick the right agent type.

  Agent types available to me:
  - Explore agent: code search, find files, grep for symbols (fast read-only)
  - Plan agent: architecture and implementation planning
  - general-purpose agent: research, web search, multi-step tasks
  - claude-code-guide: questions about Claude Code CLI, MCP, API

PART E — TOKEN SAVING STRATEGIES
================================================================================

These techniques reduce how many tokens you use per Claude session —
which saves money and keeps the context cleaner.

1. USE /compact REGULARLY
   Type /compact in Claude Code to summarize the conversation so far.
   Do this after completing each phase before starting the next one.
   Reduces context size by ~70% without losing important info.

2. START FRESH SESSIONS FOR UNRELATED TASKS
   Don't do "implement Phase 5 AND set up Husky AND fix a UI bug" in one session.
   Each session has a focused goal. Start a new claude session for each phase.

3. USE HAIKU FOR SINGLE-FILE TASKS
   Opening a Haiku session uses ~1/10th the cost of Opus.
   For documentation updates, small fixes, and boilerplate — always use Haiku.

4. GIVE ONLY RELEVANT FILES
   When asking Claude to implement auth.service.js, don't paste the entire codebase.
   Paste only: auth.service.js (if it exists), models/user.model.js, constants/index.js.

5. REFERENCE IMPLEMENTATION PLAN SECTIONS
   Instead of describing what a function should do, paste the relevant phase
   section from IMPLEMENTATION_PLAN.md. It's already written precisely.

6. USE /clear TO RESET WITHOUT RESTARTING
   Type /clear to wipe conversation history but keep the session open.
   Useful when switching to a completely different task.

7. TELL CLAUDE THE SCOPE UPFRONT
   "Only implement Phase 1 config files. Do NOT start Phase 2."
   This prevents Claude from "being helpful" and doing more than asked,
   which uses extra tokens.

8. READ FILES YOURSELF FIRST
   "Here is the current file:" [paste it] is cheaper than asking Claude
   to read it — Claude doesn't need to use a tool call.

PART F — WHICH AGENT TYPE FOR WHICH TASK
================================================================================

In Claude Code, I (Claude) can internally use specialized sub-agents
for specific types of work. You trigger these by how you phrase your request.

EXPLORE AGENT (fast code search, read-only)
  Used for: "Where is X defined?", "Which files use Y?", "Find all routes"
  Trigger phrases: "find", "where is", "search for", "which files", "locate"
  Example: "Find all files that import the Supabase client"
  Example: "Which pages in the frontend have a phone input field?"
  Cost: Very cheap — fast read-only, no writing

PLAN AGENT (architecture and design)
  Used for: Designing how to implement something before writing code
  Trigger phrases: "plan", "design", "how should I", "what's the best approach"
  Example: "Plan how to implement the Socket.io real-time notification system"
  Example: "Design the verification payment flow architecture"
  Cost: Medium — deep thinking but no code execution

GENERAL-PURPOSE AGENT (research, web search, complex multi-step)
  Used for: Questions that need web research, comparing options, complex analysis
  Trigger phrases: "research", "compare", "investigate", "look up"
  Example: "Research what the best Nigerian payment gateway alternatives to Paystack are"
  Example: "Look up the Paystack webhook documentation and summarize the event types"
  Cost: Medium

CLAUDE-CODE-GUIDE AGENT (Claude Code features and API questions)
  Used for: Questions about Claude Code CLI itself, MCP setup, hooks, API usage
  Trigger phrases: "how do I configure", "how does claude code", "mcp setup", "hooks"
  Example: "How do I configure a pre-commit hook in Claude Code settings?"
  Example: "What MCP servers are available for Supabase?"
  Cost: Medium

DIRECT (no sub-agent — I handle it in the main conversation)
  Used for: Actually writing code, editing files, fixing bugs
  Most coding work goes here — Explore/Plan/General are for research only.
